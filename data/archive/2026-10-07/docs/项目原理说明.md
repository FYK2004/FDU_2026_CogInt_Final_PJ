### 三条贯穿全局的原理

后面 12 步全部是这三条的推论，先记住它们比记住任何公式都重要。

| 编号 | 原理 | 一句话表述 |
|---|---|---|
| **P1** | **可结算性优先** | 真实事件预测的第一步不是建模，而是把模糊问题改写成**有客观结算判据的二元事件**；判据不清晰，后续所有概率都无法被评分 |
| **P2** | **生成模型 ≠ 价格聚合** | 市场价格是「被货币化的集体信念」，模型是「流程先验 + 证据条件化」的生成机制。只有两者**相互独立**，融合才有信息增量；若模型去拟合价格，融合就退化为自我复制 |
| **P3** | **概率预测要用恰当评分规则评价** | 概率预测的价值只能由严格恰当评分规则（Brier / 对数损失）度量；也正因为如此，我们输出「概率 + 区间」而不是「会 / 不会」 |

## 阶段 ①　数据采集

采集阶段的原理内核是 **P1 可结算性**：先把「题目」变成一个数学对象，再决定要采什么数据。
采集时多采的每个字段（成交量、流动性、价差）都不是装饰，它们后面会成为**判断报价可信度的依据**（见 3.3 对 11/15 节点的排除）。

### 1.1 市场侧数据采集（`collect_polymarket.py`）

**要解决的问题。** 我们需要一个「市场认为的 P(12/15 前挂牌)」，并且需要它**可分解、可追溯**，而不是一个孤立的数字。

**原理 (a)：为什么市场价格可以直接当作概率使用。**
Polymarket 的每个子市场是一份**二元合约**：结算时 Yes 付 1 美元、No 付 0 美元。
若市场参与者风险中性、且不存在显著摩擦，则无套利条件直接给出

    p = P(Yes) = E[payoff]

更深一层的原理在于**预测市场的激励设计**：这类市场使用对数市场评分规则（LMSR 一类机制），
参与者的最优策略是**如实报出自己的真实概率**（详见 P3：LMSR 对应的损失函数是严格恰当的）。
因此报价不是「观点」，而是「用真金白银约束过的信念」，可以进入我们的计算，而不只是一个参考数字。

**原理 (b)：为什么要采集整条「期限结构」，而不只是 12/15 那一个子市场。**
单个子市场只给出一个点 `F(t_k)`。而事件 `anthropic-ipo-by` 下有 10 个**按不同结算日切分**的子市场，
按结算日排序后，它们恰好是同一个函数 F(t) = P(τ ≤ t) 上的一串采样点：

    F(t_1) ≤ F(t_2) ≤ … ≤ F(t_10)

有了这条曲线我们才能做三件单点做不到的事：看出曲线上明显的 **S 形**（3.1 的关键证据）、
反推**隐含危险率**（2.1）、把「挂牌日期分布」这个看不见的变量**反解成分位数**（3.3）。

**原理 (c)：为什么要同时采集流动性、成交量、价差。**
报价的可信度**不是常量，而是可测量的**。市场微观结构的基本结论是价格噪声的方差与市场深度成反比：

    Var(p̂) ∝ 1 / (市场深度)

一个只有 9,905 美元流动性的节点，其报价的信息含量显著低于 24,114 美元流动性的节点。
这就是后面能**有依据地**把 11/15 节点剔出目标函数（而不是「看起来不对就删掉」）的基础。

**原理 (d)：为什么要采集 Kalshi 的对照市场。**
两个市场对同一命题报价同向，可以排除「单一市场定价噪声」这一替代解释：

| 市场 | 机制 | 本期读数 |
|---|---|---|
| Polymarket（链上结算，参与者以加密用户为主） | 事件 `anthropic-ipo-by` | 12/15 节点 78.5% |
| Kalshi（CFTC 监管的交易所，参与者结构不同） | `KXOAIANTH-40`：Anthropic 是否先于 OpenAI 上市 | 95% / 3%，方向一致 |

这在方法论上叫**跨市场一致性检验**：它比「单一市场内部自洽」更强，因为两个市场的参与者、
结算体系、监管环境都不同，同时出错的可能性更低。

**原理 (e)：采集层的可靠性工程。** Gamma API 提供的是 REST 元数据（事件、子市场、成交额、价差），
CLOB 的 `/prices-history` 提供小时级价格序列。二者字段不同、失败模式也不同，因此客户端必须做：
代理转发、请求重试（线性退避）、`gzip`/`deflate` 解压兜底。
这看着像工程细节，但**采集失败会直接变成模型输入缺失**，所以它是数据质量的第一道闸门。

**产物。** `data/raw/gamma_event_anthropic_ipo.json`（事件全量元数据）、
`data/raw/history/<结算日>.json`（10 个节点的小时级 Yes 价历史）、
`data/raw/kalshi_*.json`（对照市场留档）、
`data/processed/anthopic_term_structure.csv`（子市场快照表）。

### 1.2 新闻标题索引（`collect_news.py`）

**要解决的问题。** 模型参数（投资人说明日会日期、路演启动窗口、承销团）必须有**外部证据**来源，
而且这些证据要能**按时间排序**，才能构成时间线。

**原理 (a)：要采「事件」，不要采「舆情」。**
本项目不需要「市场情绪得分」，需要的是一串形如「某年某月某日，某来源报道了某个流程节点」的**离散事实**。
这也解释了为什么采集字段是 `title / publisher / published_utc / link`——它们构成一条**可排序、可回溯**的证据链，
而不是一段文本。情绪指标与「S-1 何时递交」这类事实是两类东西，前者无法写进模型。

**原理 (b)：为什么要用多组查询词。**
单一查询词会带来**检索偏差**：只搜 "Anthropic IPO" 会漏掉关于文书（S-1）、估值、具体月份的报道。
本项目用 4 组语义面向覆盖四类证据：

    anthropic_ipo（流程） / anthropic_ipo_nov（时程）
    anthropic_s1（文书） / anthropic_valuation（规模）

**原理 (c)：为什么优先用 RSS 而不是直接爬网页。**
RSS 是**结构化 XML**：字段固定、标签稳定、几乎无模板噪声，解析成本远低于网页；
并且 `pubDate` 提供带时区的时间戳，可以统一换算成 UTC——**只有统一时区，才能与 Polymarket 的数据对齐**
（2.3 的跳变↔新闻对照完全依赖这一点）。

**原理 (d)：去重原理。** 一条事实常被多家媒体转载。若不去重，同一事实会被计成多条证据，
形成**重复计数偏差**。因此按标题小写去重、保留最早出现的一条。

**产物。** `data/raw/news_<query>.xml`（4 份原始 RSS）、`data/processed/news_index.csv`（286 条去重后的标题索引）。

### 1.3 正文抓取与正文抽取（`fetch_articles.py` + `html_to_text.py`）

**要解决的问题。** 标题只能定位事件，**参数的取值**（「路演最快 11/9 当周启动」「承销团为摩根士丹利、高盛、摩根大通」）
藏在正文里，必须把正文取下来才能作为建模依据。

**原理 (a)：正文抽取 = 从 DOM 里去掉噪声，保留可见文本。**
网页文本的噪声来自两类：不可见内容（`<script>`/`<style>`/`<noscript>`）与标记本身。
因此抽取流程是一个**逐层剥离的启发式**：

    删除 script/style/noscript 整块
      → 块级标签（p/div/br/li/h1–h6/tr）替换为换行（保留段落结构）
      → 删除剩余所有标签
      → HTML 实体反转义（&amp; → &）
      → 折叠空白与多余空行

这是最轻量的 readability 近似：不需要浏览器渲染引擎，代价是偶尔保留少量导航文字，
但对「定位日期、机构名」这类任务已足够。

**原理 (b)：链接必须二次解析。** Google News 给的是跳转链接，必须先跟随重定向拿到真实 URL
（必要时从返回页面里提取 `data-n-au` 或第一个站外 `<a href>`），否则抓到的永远是跳转页而不是文章。

**原理 (c)：失败要显式记录，而不是悄悄跳过。**
Reuters / WSJ / Bloomberg 有付费墙，正文抓不到是**预期的失败**，不是异常。
正确做法是：记录失败、保留 URL 与抓取日期、转向可获得的二手转述（中央社、工商时报、INSIDE、Yahoo Finance）。
这引出本项目的**证据纪律**：只采信**至少两家独立来源交叉印证**的要点，并保留链接与时间戳以便审计。

**产物。** `data/raw/articles/*.txt`（15 篇正文）+ `_manifest.csv`
（`name / title / publisher / date / url / chars`——最后两个字段让「这条证据有多少字、出自哪」可查）。

## 阶段 ②　数据处理

处理阶段的原理内核是**「把数据变成函数」**：把一堆报价点变成一条 CDF、一列时间序列、一组结构性事件，
以及一个能**检验建模假设**的诊断量（隐含危险率）。

### 2.1 期限结构构建与隐含危险率（`analyze_term_structure.py`）

**要解决的问题。** 拿到 10 个子市场的报价后，要回答两个问题：它们怎样拼成一条曲线？
这条曲线的形状**支持还是否定**「无记忆随机事件」的建模方式？

**原理 (a)：必须按结算日排序。**
F(t) 是日期的单调函数，只有按 `endDate` **升序**排列，报价序列才是 CDF 的采样点，才具有「生存曲线」的含义。
若按标题字母序（或任意顺序）排列，得到的只是一个无意义的数字串——这一步看着琐碎，却是后续一切的前提。

**原理 (b)：隐含危险率的反演（本步真正的核心）。**
设生存函数 S(t) = P(τ > t) = 1 − F(t)，即「到 t 为止还没挂牌」的概率。
若挂牌过程是**无记忆**的——即每天以某个常数强度 λ 发生（等价于泊松过程 / 几何分布）——
则生存函数必然是纯指数形式：

    S(t) = e^(−λt)

反过来，如果两个相邻节点确实来自同一个指数生存函数，它们**必须**满足

    h = − ln( S(t_k) / S(t_k−1) ) / Δt × 365        （Δt 单位为天，×365 得到年化值）

于是把这条恒等式当作**检验**使用：对每一对相邻节点反解一个 h，

| 观测结果 | 结论 |
|---|---|
| h 沿曲线基本恒定 | 支持常数强度（泊松 / 几何）建模 |
| h 沿曲线数量级变化 | **拒绝**无记忆假设，必须引入结构（分阶段）建模 |

本项目实测属于第二种，这是 3.1 选择「门控时间线」的**实证依据**，而不是主观偏好。
换句话说：**先由数据否定简单模型，再提出复杂模型**——这个顺序本身就是方法论的一部分。

**实现要点。** 用 `prev_p / prev_end` 滚动指针；只在 `p_k < p_{k−1}` 时计算（否则对数无意义或给出负危险率）；
无法计算时留空而不是填 0。

**产物。** `data/processed/term_structure.csv`，字段包括
`deadline / end_date / yes_price / implied_prob_pct / annualized_hazard_pct / volume_usd / liquidity_usd / spread / closed / history_points`。

### 2.2 宽表重建（日度面板对齐）

**要解决的问题。** 10 个节点的价格历史是**各自独立、时间戳杂乱**的小时级序列。
如果直接比较「各自最新的一条」，就会把不同时刻的价格放在一起比。

**原理：非同步观测（asynchronous observation）问题。**
金融数据的经典陷阱：两个资产看起来有分歧，其实只是**观测时刻不同**。
解法是把所有序列**重采样到统一的 event-time 网格**上——本项目取 **UTC 日**为网格，每个节点取当日最后一个观测作为日收盘价。

**三个具体的设计选择及其理由。**

| 选择 | 理由 |
|---|---|
| 网格用 UTC 日 | Polymarket/新闻/CLOB 时间戳都是 UTC，统一到 UTC 日避免跨时区错位 |
| 取「最后一个观测」而不是「日均值」 | 收盘价代表市场在当日信息集下的最终共识；均值会混入信息到达前的旧价与日内噪声 |
| 缺失值留空，**不插值** | 插值等于伪造信息；空档期本身是有意义的信号（该节点当时无人关注） |

**产物。** `data/processed/history_wide.csv`（行 = 日期，列 = 10 个节点，单元格 = 当日收盘 Yes 价）。

### 2.3 跳变检测（事件研究）

**要解决的问题。** 「IPO 分阶段推进、市场按阶段重定价」是模型的核心假设。
这个假设不能只靠推理，需要**可观测的经验支持**。

**原理 (a)：价格跳变是「信息到达」的代理变量。**
这是事件研究（event study）的基本思路：价格在某日大幅变动，说明当日有信息到达。
把每个节点的日度变动 |Δp| 排序、取绝对值最大的前 8 天，
就得到一组**候选重定价事件**；再与 1.2 的新闻时间线对照，即可检验因果对应关系。

**原理 (b)：为什么用 top-k 而不是设定阈值。**
样本规模小（10 个节点 × 数百天），阈值需要额外标定且对节点间波动差异不稳健；
top-k 无参数、可解释，且正好满足出图（图 2 的事件标注）的需要。

**原理 (c)：为什么用日度差而不是小时差。**
新闻只有**日期粒度**。若用小时差，同一条新闻造成的连续调整会被拆成多段，
既不利于与新闻对齐，也会人为放大跳变数量。

**本步的结果（也就是它对模型的贡献）。**

| 日期 | 现象 | 对应证据 | 对假设的意义 |
|---|---|---|---|
| 9/18–9/19 | 全曲线暴跌（10/31 节点单日 −50.35pp） | WSJ：IPO 推迟至 11 月 | 市场按「时程」整体重定价 |
| 10/01 | 全曲线反弹（11/30 节点 +11.0pp） | Bloomberg：10/14 说明日会 + 路演最快 11/9 当周 | 市场按「里程碑门」重定价 |

**产物。** `data/processed/jump_events.csv`（`slug / date / delta_pp / from / to`）。

## 阶段 ③　建模与校准

这是项目的主体，也是原理最密集的部分。一句话概括：**用「流程结构」替代「无记忆假设」，
再用受证据约束的轻校准把系统性偏差修掉，最后与市场做 log-odds 融合。**

### 3.1 门控蒙特卡洛引擎（`model_core.py`）

#### (a) 为什么先要淘汰「无记忆」模型

**问题。** 最朴素的建模方式是：设「某天挂牌」为每日常数概率 q 的伯努利试验，则

    P(τ = t) = (1−q)^(t−1) · q　（几何分布）　⇒　S(t) = (1−q)^t　（指数形）

**为什么它必然出错——两个独立的理由。**

1. **形状错。** 指数生存函数的危险率是常数，而实测 h 沿期限结构剧烈变化（2.1）。
2. **信息用不上。** 指数分布具有**无记忆性**：

       P(τ > t + s | τ > t) = P(τ > s)

   意思是「已经等了 5 个月」对「下一个月的概率」毫无影响。但现实恰恰相反：
   一旦某道门（如 10/14 说明日会）被公开证据确认，整条曲线的剩余部分应当**立刻抬升**；
   无记忆模型无法表达这种**条件化更新**——而这正是本项目最想利用的信息（见 4.2）。

**替代方案逐一对比（为什么最后落在「分段 + 三点估计 + 硬约束」上）。**

| 候选模型 | 形式 | 淘汰理由 |
|---|---|---|
| 几何 / 泊松 | 常数危险率，S = e^(−λt) | 形状与实测不符；无法使用「门被锁定」的信息 |
| 正态 N(μ, σ²) 直接对挂牌日建模 | 对称、支撑集为全体实数 | 挂牌日不可能为负、右偏，且无法容纳「年内不挂牌」这一吸收态 |
| 对数正态 / 威布尔 | 右尾可控；威布尔危险率单调 | 参数无法由报道直接给出（众数、上界无先验依据）；真实危险率**非单调**（路演前≈0，路演后骤升），威布尔表达不了 |
| 专家直接给一个日期 + 误差条 | 无分布假设 | 无法给出条件概率、无法给区间、无法回应对判决点的敏感度 |
| **本项目：门控时间线 + 三角分布 + 硬约束 + 吸收态** | τ = t0 + Σ Δj | 保留——每一步的参数都能指向一条公开报道 |

#### (b) 门控时间线的构造

**原理。** 超大型 IPO 不是「随机某天发生」，而是**必须依次通过若干道门**：

    秘密递交 S-1 → 公开招股书 / 投资人说明日会 → 正式路演 → 簿记与定价 → 首个交易日

于是不必对「何时挂牌」设一个无结构的概率，只需对**每一段的历时**建模：

    D_i = t0 + Δ_gap,i + Δ_road,i + Δ_lag,i ( + Δ_slip,i )

在数学结构上，这是一个**半马尔可夫 / 相位型（phase-type）过程**：状态 = 已通过的门数，
每个状态的驻留时间 = 该段历时。已被公开证据锁定的门，则**把某段的起点固定为一个已知日期**（条件点 / 硬约束）。
本项目中被锁定的门是 t0 = 2026-10-14（Bloomberg 报道并经邀请函证实的 Pre-IPO 投资人说明日会）。

**这一步换来两件关键能力。**

1. **条件化更新**：证据变化时只改一个参数（如把 t0 重新锚定），结果立即刷新；
2. **任意日期可查询**：因为它是**生成模型**，对任意 t 都能算出 F(t)——而市场只有节点报价，
   这正是 4.2 条件概率增量的技术根源。

**代价（要诚实声明）。** 把各段视为独立会忽略阶段间相关性（例如「整体延期」会同时拉长 Δgap 与 Δroad）。
本项目的补救方式是额外设置一条「延期支线」Δslip（见 (e)），而不是假装独立假设完全成立。

#### (c) 为什么用三角分布

各段历时取**三角分布**，参数为 (a, b, c) = (下界, 众数, 上界)，单位日历日：

    f(x) = 2(x−a) / ((b−a)(c−a)) ,  a ≤ x ≤ c
    f(x) = 2(b−x) / ((b−a)(b−c)) ,  c < x ≤ b
    E[X] = (a + b + c) / 3
    Var[X] = (a² + b² + c² − ab − ac − bc) / 18

**为什么是它而不是正态 / 均匀 / Beta。**

| 分布 | 优点 | 为什么不用 |
|---|---|---|
| 正态 | 数学方便 | 支撑集无界，会给「负数天」与「无限长延期」正概率 |
| 均匀 | 最简单 | 无法表达「众数在某处」的行业经验 |
| Beta / 对数正态 | 形状灵活 | 参数（α, β）无法由一条报道直接读出，失去**可解释性**，评审时无法自证 |
| **三角** | 三点估计可直接由报道与行业经验给出；有界；可偏斜 | 保留——代价是假设密度线性，属于可接受的结构简化 |

**「上界」的语义要说清楚。** 三角分布的 b 只是**支撑集边界**，不代表「不可能超过」。
正因如此，才需要一条独立的 slip 支线去承载超出主路径右界的情形（见 (e)）。
这也是「右尾有限」与「不会无限拖延」这一行业直觉的定量表达。

#### (d) 离散化与日历约束（这一节的原理最容易被忽略）

**问题。** 连续分布会把概率质量放在**现实中不可能发生的日期**上：周末启动路演、感恩节当天挂牌。
这不是审美问题，而是**系统性偏差**。

**原理：把连续分布的质量重新分配到「可行日期集合」上，等价于对可行支撑集做条件化。**
本项目的三条日历约束及其后果：

| 约束 | 理由 | 若不加会怎样 |
|---|---|---|
| 路演启动日 snap 到周一 | IPO 路演不会在周末启动 | 约 2/7 的路径会落在不可能的日子上，并把左边尾部的概率系统性拉早 |
| 挂牌日 snap 到周一 | 大额 IPO 的首日通常安排在周一，以配合定价与路演节奏（比「工作日」更强的约束，属**偏保守**设定） | 概率质量落在非交易日；同时会抹掉 11/23 的周一尖峰 |
| 避开感恩节 11/26 | 美国市场休市，不可能挂牌 | 给一个概率为零的日子正概率 |

**实现注意。** snap 必须**迭代到收敛**：向前推 1 天有可能又落到周末（例如周六 → 周一，但若原日期是周日则只需 +1）。
因此代码里循环（至多 3 次）直到不再有需要推的路径，保证结果落在可行集合内。

顺带解释报告里的一个现象：校准后挂牌日分布在 **11/23（周一）出现 16.3% 的尖峰**，
这正是「11/9 当周启动路演 + 约两周簿记」这条主路径与「snap 到周一」共同作用的产物——
**约束不是装饰，它会直接改变分布形状**。

#### (e) 竞争风险与吸收态 `stall_prob`

**原理。** 并非所有路径都以「挂牌」结束。真实世界存在**竞争风险**：被收购、撤回申请、
估值谈崩、窗口关闭——这些都会让本题结算为 No。

**为什么合并成一个吸收态。** 本题只关心二元事件 {τ ≤ T}，不需要区分 No 的原因；
区分反而会引入无法识别的参数（我们没有足够数据分别估计四种退出原因的概率）。
于是模型是一个**混合分布**：

    F(t) = (1 − p_stall) · F_live(t) ,   余下 p_stall 的质量落在 τ = ∞（本年不挂牌）

即：以概率 `p_stall` 走「永不挂牌」的路径，其余路径按门控时间线分布。

**独立佐证（这一点体现「校准纪律」）。** 校准得到的 `p_stall` = 0.19，
而市场期限结构隐含「有 17.5% 的概率落在 2027 年及以后」——两个完全独立的量互相印证。
**一个校准出来的参数若能由另一条独立证据解释，它才叫校准；否则只是拟合。**

#### (f) 为什么用蒙特卡洛而不是解析解

**原理。** 时间线上叠加了四层复杂度：n 段三角分布之和、离散 snap 与假日避让、
混合吸收态、以及后续的任意日期条件查询。此时闭式解要么不存在，要么推导成本远高于收益。

蒙特卡洛用**大数定律**直接绕开卷积：把「n 个分布相加」变成「采样 n 次再相加」，
用经验分布函数近似理论分布：

    F̂(t) = (1/N) · Σ_i 1{ τ_i ≤ t }        SE(F̂) ≈ √( p(1−p) / N )

**为什么 N = 400,000 就够（用数字回答，而不是「越大越好」）。**

| 路径数 N | p ≈ 0.8 时的标准误 | 用途 |
|---|---|---|
| 12,000 | ≈ 0.37 pp | 阶段一粗网格（只需区分大误差） |
| 40,000 | ≈ 0.20 pp | 阶段二细化、敏感性曲面 |
| **400,000** | **≈ 0.06 pp** | 最终精算：采样误差比模型不确定性小一个数量级以上，可忽略 |

这个「用 SE ≈ √(p(1−p)/N) 决定路径数」的推理贯穿 3.3：**网格分辨率必须与 MC 噪声匹配**，
否则「最优点」只是在挑噪声。

**可复现性。** 全流程使用固定种子 `20261007`，因此任何人重跑都得到同一串数字——
对课程提交而言，「可复现」比「精度高一点点」重要得多。

### 3.2 未校准基线（`milestone_model.py`）

**要解决的问题。** 如果最终答案只是一个「读了市场价格之后再调整的数字」，就无法回答
「模型到底有没有带来增量」。

**原理 (a)：对照实验（消融）。** 基线是**完全不用市场信息**的极端设定：
所有参数取 3.1–3.2 的报道先验值，不拟合任何报价。它的作用是提供一个**可比较的参照点**：

| 版本 | P(12/15) | 中位挂牌日 | 与市场之差 |
|---|---|---|---|
| 市场 | 78.5% | 11/26（隐含） | — |
| **未校准基线** | **84.67%** | **11/30** | **+6.17pp** |
| 校准后模型 | 80.96% | 11/24 | +2.46pp |

基线的偏差（+6.17pp、中位晚 4 天）**本身就是信息**：它量化了「只凭报道先验」会**同时**
偏乐观（概率偏高）又偏慢（日期偏晚）——这两件事看起来矛盾，其实是同一件事：先验把概率堆在了
感恩节之后那段更宽的时间窗里。

**原理 (b)：参数必须先注册、后校准（pre-registration 精神）。**
若先看市场再设定参数，「模型与市场独立」（P2）就不成立，融合也就没有意义。
因此执行顺序被固定为：**先验参数 → 基线 → 再看市场 → 才允许轻校准**。

**原理 (c)：这一步还是对「结构假设」的检验。** 门控模型即使完全不校准，
也能复现市场曲线**明显的 S 形**（只是整体前移）。**形状对、参数偏**说明结构设定是对的、
需要修的是尺度；反之若连形状都不对，就应该推翻结构而不是调参数。

**产物。** `baseline_model_vs_market.csv`、`baseline_summary.json`。

### 3.3 三阶段校准 + 市场融合（`calibrate_model.py`）

#### (a) 目标函数与「校准 ≠ 拟合」的界限

**原理。** 校准用一个显式的损失函数把模型的 CDF 与市场报价对齐：

    L(θ) = Σ_k w_k · ( F_model(t_k ; θ) − P_market(t_k) )² × 100²      （单位：pp²）

对 3 个活跃节点取 `w_k` = 1。为什么用**平方误差**：它是概率预测的标准损失（Brier 分数的加权形式），
处处可微、凸性良好，且单位（pp²）直观，便于与基线直接比较。

**关键区分：什么时候是「校准」，什么时候只是「拟合」。**

| | 拟合（本项目的纪律所禁止） | 校准（本项目允许的） |
|---|---|---|
| 自由度 | 想加多少加多少 | 只调 4 个参数，且每个都对应一段可报道的流程 |
| 结果解释 | 不要求 | **必须**能用地上的公开证据解释 |
| 目的 | 最小化误差 | 修正**系统性**偏差（先验整体偏慢一周） |

这套纪律的作用是让「最优解」**可被外部检验**：最优解 `gap = (16, 24, 40)` 天
意味着「10/14 说明日会 + 24 天 ≈ 11/7 的路演启动」，与「路演最快 11/9 当周启动」的报道一致。
如果最优解指向「10/14 后 3 天就启动路演」，那就应当**修改模型结构**，而不是欣然接受这个拟合结果。

#### (b) 为什么分三阶段搜索

**原理：计算成本与分辨率的权衡，外加 MC 噪声的限制。** 全场联合搜索的网格点数量是各维度乘积，
而每个点的模拟成本固定，因此必须在「广度」与「精度」之间分阶段配置资源：

| 阶段 | 搜索内容 | 网格规模 | 路径数 / 每点 | 目的 |
|---|---|---|---|---|
| 一（粗） | `stall_prob × gap_mode × gap_high × roadshow_high` | 780 组 | 12,000 | **广域定位盆地**，避免陷入局部极小 |
| 二（细） | 在阶段一最优点邻域 ±7 / ±15 天细化 | 405 组 | 40,000 | **提高分辨率**（此时 MC 噪声须同步降低） |
| 三（一维） | `slip_share` 单独搜索 | 6 个值 | 40,000 | 只影响**右尾形状**，先定左侧再定右尾（坐标下降思想） |

**为什么路径数随精度提高（本步最容易做错的细节）。** 阶段一每点 12k 路径的 SE ≈ 0.37pp，
而网格步长是「天」量级、造成的概率差远大于 0.37pp，因此**够用**；
阶段二的步长缩小到 ±7 天，概率差可能只有 1pp 左右，若不把路径数提到 40k（SE ≈ 0.20pp），
选出的「最优点」就可能只是噪声。**先算噪声水平，再决定网格分辨率**——这是蒙特卡洛校准的通用规则。

#### (c) 参数空间被证据裁剪

搜索时对参数施加上下界，其中最有原理性的一条是：

    gap_mode ≥ 24 天　（10/14 + 24 = 11/7，即「11 月 9 日当周启动」报道所能容许的最早值）

**原理。** 这不是数值稳定性处理，而是**把「先验必须有证据支撑」形式化**：
参数空间只保留能被公开报道解释的区域，禁止搜索「10/14 后立刻启动路演」这类无证据支持的可能。
同理，三角分布要求 a < c < b，并在网格取整越界时兜底修正——保证每次模拟的参数都合法。

#### (d) 为什么必须有「延期支线」（结构性缺口的正确处理方式）

**问题。** 若没有 Δslip，时间线存在一个**硬右边界**：
超过它的路径概率为零，于是 F(12/15) 恒等于 F(12/31)。
但市场让 12/31 比 12/15 高 **4pp**——市场承认存在少量「12 月上中旬才完成定价」的情形。

**原理。** 模型与数据之间的这种偏差是**结构性**的，不能靠加噪声或调松某个上界来「凑」，
而应当**补一个结构**：以概率 `slip_share` 触发一条支线，模拟「路演结束后仍未定价，
需重新接触投资人 / 补充材料 / 等待窗口」的情形，从而自然地把少量质量放到 12 月上中旬。

**一般化的教训。** 结构性问题要结构性地修（加分支），参数性问题才调参数。
混淆二者的典型症状就是「为了对齐一个数字，把某个参数调到不合理的值」。

#### (e) 为什么把 11/15 节点排除在目标函数之外

**问题。** `november-15-2026` 节点报出 13.0% 的 Yes 价，即市场认为「11/15 前完成挂牌」有 13% 概率。
但报道说路演最快 11/9 当周启动，此后还需约两周簿记、定价、首日交易——**11/15 前挂牌在时序上几乎不可能**。

**两条可量化的排除依据。**

1. **时序矛盾**：与已写入模型硬约束的「11/9 当周启动路演」直接冲突；
   也可能反映该节点的**结算口径不同**（例如参与者按「宣布」而非「挂牌」理解）——两种解释都使其不可与其余节点并列。
2. **流动性最薄**：9,905 美元，仅为 12/15 节点的 41%、12/31 节点的 32%。
   由 1.1 的 Var(p̂) ∝ 1/深度，薄市场的报价方差大得多，**可信度更低**。

**原理（鲁棒统计的取舍）。** 异常观测的处理有两种正统做法：用稳健损失（M-estimator / Huber）自动降权，
或**显式剔除并披露**。本项目选后者，理由是：n = 3 的目标节点太少，稳健估计的渐近性质不成立，
而**显式披露**在学术规范上更透明。反过来说，若不处理，这个噪声观测会因为「偏差最大」
而在最小二乘里获得最大杠杆（outlier leverage），把有证据支撑的参数**整体拉偏**。

**这句处理方式本身就是本项目的建模立场：宁可与一个异常报价保持分歧，也不让个别噪声观测污染有证据支撑的参数。**
该节点的偏离量在报告 §6.2 单列为「市场异常披露」，而不是被悄悄拟合掉。

#### (f) 融合：为什么用 log-odds 加权而不是算术平均

**原理。** 我们有**两个相互独立的概率源**（P2）：模型的 `p_model` 与市场的 `p_market`。
融合方式的选择取决于「什么运算对独立证据是自然的」。

概率是有界量 [0, 1]，算术平均会在两端严重失真（两个 0.01 与两个 0.99 被同等对待；
且「概率平均」不对应任何贝叶斯操作）。而 **logit 变换把 [0, 1] 拉到全体实数 ℝ**：

    logit(p) = ln( p / (1−p) ) ,    σ(z) = 1 / (1 + e^(−z))

在 log-odds 尺度上，「独立证据的**似然比相乘**」变成了**加法**——这正是朴素贝叶斯的线性形式。
因此加权平均 log-odds 就等于「让每个来源按自己的可信度贡献一份对数似然比」：

    p_final = σ( w · logit(p_model) + (1 − w) · logit(p_market) )

**权重取的原理（为什么 w = 0.35 而不是 0.5）。** 三条理由都指向「偏向市场」：

1. 市场是**连续更新**的，包含模型未采样的信息（资金流、持仓结构、未公开的传闻）；
2. 模型参数在校准时**用到了同一批报价**，存在过拟合风险，应主动压低其权重；
3. 单一事件预测中，模型的结构先验**样本支持度弱**（只有一个事件）。

但权重本身也做了敏感性分析，结论对 w 不敏感：

| 模型权重 w | 0.00 | 0.25 | **0.35** | 0.50 | 0.65 | 1.00 |
|---|---|---|---|---|---|---|
| P(12/15) | 78.5% | 79.1% | **79.4%** | 79.8% | 80.1% | 81.0% |

原因其实很朴素：**两个源在 log-odds 空间里本来就靠得很近**，任何合理的凸组合都落在两者之间。
这也提示了正确解读——**edge 只有 +0.89pp，真正的信息量不在点位**（见 4.2）。

#### (g) 区间为什么取「参数邻域 × 权重」的包络

**原理。** 不确定性来自两个**正交**的方向：模型参数/结构（用 `stall_prob ± 0.03` 的邻域代表）
与聚合权重（0.25 / 0.35 / 0.50）。取二者的**包络（最坏组合）**而非「方差合成」的理由是：

- 这两类不确定性不是同一个随机变量，无法假设独立同分布地相加；
- 单事件预测最大的风险是**假精确**（给出一个漂亮数字却无不确定性表述）；
- 包络法虽然保守，但**不会低估**不确定性，符合「宁可区间宽、不要区间失真」的原则。

结果是 80% 区间 **78.3%–81.4%**——这个宽度本身就是结论的一部分：
它说明模型与市场的高度一致，而不是给出一份虚假的精确。

#### (h) 条件概率：本项目的核心增量从哪来

**原理（贝叶斯条件化）。** 由 F 可以直接得到条件概率：

    P(τ ≤ T | τ > t_s) = ( F(T) − F(t_s) ) / ( 1 − F(t_s) )

**为什么市场给不出这个数。** 期限结构只提供**节点上**的 `F(t_k)`，而 11/26（感恩节）不是节点。
市场要算这个条件概率，只能用**线性插值**得到 F(11/26)——而线性插值等价于假设
「相邻节点之间每天的挂牌密度均匀」，这本身是一个**未被市场定价的额外假设**。
模型则是生成式的：任意 t 都能直接算出 F(t)，不需要插值。

**所以增量的本质不是「我们的数字更准」，而是「我们能表达一个市场结构上无法表达的量」。**
实测结果为 **模型 64.3% vs 市场 55.8%**，两者相差 +8.5pp，是整个项目里分歧最大的一处。

**同时必须声明插值的固有偏差。** 同一个线性插值假设用到 12 月中下旬更不成立
（超大型 IPO 不会在圣诞前后两周定价），因此市场隐含的 12 月窗口概率应视为**上界**。

**情景 B（路演顺延）的原理。** 把「路演是否如期启动」当成不确定变量，整体平移 Δgap：

| 情形 | P(12/15) | 中位挂牌日 |
|---|---|---|
| 基准 | 81.0% | 11/24 |
| 路演推迟 1 周 | 80.6% | 12/01 |
| 路演推迟 2 周 | 73.2% | 12/08 |

这实际上是一次**部分识别**检验：结论在合理扰动下不变（始终显著大于 2/3、始终判定 Yes），
但**精确定位敏感**——这正是「给区间、压低融合权重、并在报告里显式披露判决点」的完整理由。

**产物。** `data/processed/forecast.json`（最终预测与全部参数）、`final_model_vs_market.csv`、
`bucket_implied.csv`（分桶对照）、`sensitivity_grid.csv` / `sensitivity_surface.csv` / `sensitivity_slip.csv`、
`listing_date_hist.csv`。

## 阶段 ④　结果输出

### 4.1 最终预测（`forecast.json`）

**原理 (a)：为什么用单一 JSON 作为「唯一事实源」。**
报告、README、图表里的每一个数字都必须能指向 `forecast.json` 的一个字段。
这样做的收益是双重的：**消除手抄错误**（数字只在算完之后被引用一次），
以及**可审计**（评审可以逐字段核对）。README 因此写明「若现场演示与报告不一致，以本地数据文件为准」。

**原理 (b)：概率预测的三要素。**

    P(Anthropic 在 2026-12-15 前完成 IPO) = 79.4%　　（80% 区间 78.3%–81.4%）　⇒ 判定 Yes

输出必须是**点估计 + 区间 + 判定阈值**三件套：

- 只给「会 / 不会」会丢掉全部不确定性信息；
- 只给点估计会鼓励「假精确」；
- 有了区间，才能在结算后用**恰当评分规则**检验（P3）：

      Brier = (p − o)²          （o ∈ {0,1} 为实际结果）
      对数损失 = − [ o·ln p + (1−o)·ln(1−p) ]

这两个损失函数都是**严格恰当**的：只有如实报告自己的真实信念，才能最小化期望损失。
这也反向解释了为什么预测市场的报价可以被当作概率使用（1.1）。

**原理 (c)：edge 的解读纪律。** 相对市场的 +0.89pp 很小，**不应**被解读为「发现了套利机会」。
它的正确表述是：「两个近乎独立的预测源之间**可测量**的分歧」。
真正有信息量的是 4.2 的条件结构——这也是本项目反复强调的结论。

### 4.2 核心增量：条件概率（情景分析）

**原理：边缘相同 ≠ 条件结构相同。**
两个预测源完全可以在 12/15 这个**边缘概率**上几乎一致（79.4% vs 78.5%），
却在「已经过了感恩节还没挂牌」这个**条件世界**里给出 64.3% 与 55.8% 两种不同的判断。

这一点在方法论上很重要：**仅比较点位会误判两个模型「一样好」或「没差别」；
条件概率才是对模型结构的更尖锐的检验**，因为它同时约束了曲线在多个点上的位置。
报告因此把条件概率单列为本项目的「核心增量」，而不是把 +0.89pp 当作卖点。

**情景 A 的意义。** 市场把「感恩节前挂牌」与「12/15 前挂牌」高度绑定
（市场隐含感恩节前概率 51.3%），而门控模型认为感恩节之后仍有约两周的可挂牌窗口
（11/30 – 12/12），因此条件概率高得多。这个差别的**来源是结构，不是数字**：
市场用一条平滑插值曲线隐含了「密度均匀」，模型则显式表达了「感恩节是硬约束、节后另有一个窗口」。

### 4.3 图表与报告（`make_figures.py`、`make_pipeline_figure.py`、`build_report_docx.py`）

**原理 (a)：每张图承担一个论证环节，不做装饰性插图。**

| 图 | 回答的问题 | 支撑正文的哪一步 |
|---|---|---|
| fig0 流程图 | 整个项目是怎么串起来的 | 全文导览 |
| fig1 期限结构 | 曲线是否呈 S 形、各节点报价与流动性 | 2.1、5.1 |
| fig2 历史 + 事件标注 | 市场是否按里程碑重定价 | 2.3、5.1 |
| fig3 生存曲线对照 | 基线 / 校准 / 市场三者的位置关系 | 3.2、3.3、5.3 |
| fig4 分桶对照 | 分歧具体落在哪个时间窗 | 5.4 |

**原理 (b)：可复现纪律——图必须由脚本生成，不手改 PNG。**
手工修图会让「图」与「数据」脱钩，下次重跑就产生矛盾版本。

好处是**不会产生两份相互漂移的文稿**；版式（页数控制）交给渲染脚本负责，写作时只需专注内容。

## 附录 D　易错点清单（Pitfalls）

1. **按标题字母序排列子市场** → 得到无意义的锯齿，必须先按 `end_date` 升序（2.1）。
2. **用小时差做跳变检测** → 同一条新闻被拆成多段；新闻只有日期粒度（2.3）。
3. **snap 只做一次** → +1 天可能再次落在周末，必须迭代到收敛（3.1(d)）。
4. **网格步长小于蒙特卡洛噪声** → 选出的「最优点」是噪声；先算 SE 再定分辨率（3.3(b)）。
5. **用市场报价去定先验参数** → 破坏 P2 的独立性，融合失去意义（3.2(b)）。
6. **把线性插值当成市场「真实」信念** → 插值自带「密度均匀」假设，12 月窗口应视为上界（3.3(h)）。
7. **为了让数字更对齐而放宽参数上界** → 结构性缺口要补结构，不要调参数（3.3(d)）。
8. **手改 PNG 或手抄数字** → 图与数据脱钩；一律改脚本重跑（4.3(b)）。
